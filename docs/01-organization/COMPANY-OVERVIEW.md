## 6. Engineering Principles

### Core Architectural Tenets (from portfolio document)

1. **Understand Before Architecting:** Technical designs must follow documented, client-confirmed operational problem statements.
2. **Structural Integrity Over Patches:** Solutions address systemic architectural causes, never brittle short-term bypasses.
3. **Clear Module Boundaries:** Domain business logic resides within decoupled service pipelines, separated from transport layers.
4. **Security & Performance by Default:** Minimal database lock windows, composite indexing, automated payload sanitization, and comprehensive audit logging are mandatory.
5. **Institutional Knowledge Preservation:** All architectural decisions, data models, and operational lessons must be documented systematically.

### Three-Tier Standardization Ladder

| Tier | Trigger | Execution |
|---|---|---|
| **Tier 1: Client-Specific Customization** | Unique to a single client's proprietary workflow | Isolated configuration hooks, never alters core platform |
| **Tier 2: Generalized Reusable Capability** | Multiple clients share the same underlying need | Abstract, configurable core module |
| **Tier 3: Industry-Wide Standard** | Universal or statutory regulation | Natively incorporated into industry product |
